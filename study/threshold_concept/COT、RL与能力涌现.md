# CoT、RL 与能力涌现

本文整理我们围绕以下问题展开的讨论：

1. CoT 是什么，它为什么能帮助模型推理？
2. CoT 是通过 SFT 教出来的，还是通过 RL 自己探索出来的？
3. 为什么只奖励最终答案，也可能让更长的推理、反思和自我纠错逐渐出现？
4. DeepSeek-R1-Zero 的 “Aha Moment” 应该怎样理解？
5. 同样使用 RL，为什么不同模型的推理、数学和编程能力仍有巨大差距？

基础的 SFT、Policy Gradient、PPO、GRPO 和 loss 公式见 [`对比SFT与强化学习来学习RL.md`](对比SFT与强化学习来学习RL.md)。

---

## 1. CoT 是什么？

CoT 全称 **Chain of Thought（思维链）**。对大语言模型而言，它是最终答案之前生成的一段中间推理 token。

没有 CoT：

```text
问题：小明有3个苹果，吃掉1个，又买了2个，现在有几个？
回答：4
```

有 CoT：

```text
小明原来有3个苹果。
吃掉1个后剩下2个。
又买了2个，所以现在有4个。
答案是4。
```

从模型机制上看，CoT 并不是模型内部新增了一个符号推理器。它仍然在做 next-token prediction，只是把部分中间计算显式写进上下文：

```text
题目
  → 中间推理 token 1
  → 中间推理 token 2
  → 中间结论
  → 最终答案
```

这些中间 token 又会成为后续 token 的输入，因此模型获得了更多“计算步骤”和外部可见的工作记忆。

---

## 2. 为什么生成更多 token 可能提高推理能力？

Transformer 的一次 forward 对固定上下文执行有限层数的计算。如果模型直接输出答案，相当于要求它在很少的生成步骤内完成整个问题。

CoT 将复杂问题拆成多个阶段：

```text
理解问题
→ 提取已知条件
→ 选择方法
→ 执行中间计算
→ 检查结果
→ 输出答案
```

每生成一个新 token，模型都会再次对“题目 + 已有推理”进行计算。于是生成过程本身提供了额外的 test-time compute。

这不意味着“越长越聪明”：

- 有效的中间步骤可以帮助推理；
- 无意义重复只会浪费 token；
- 错误中间步骤也可能不断强化错误上下文；
- 过长回答可能发生迷失、截断或奖励投机。

真正重要的是：模型是否学会使用这些额外 token 进行有效分解、验证和纠错。

---

## 3. CoT 的第一条来源：通过 SFT 模仿标准推理

SFT 可以直接提供带推理过程的标准答案：

```text
Prompt：数学问题
Target：完整推理过程 + 最终答案
```

交叉熵会逐 token 提高标准推理轨迹的概率：

\[
L_{\mathrm{SFT}}
=-\frac{1}{N}\sum_t
\log p_\theta(y_t\mid x,y_{<t})
\]

这条路线的优势是：

- 训练信号密集，每个 token 都有 target；
- 很容易教会统一的格式；
- 能快速建立基本推理习惯；
- 可以控制语言、结构和可读性。

局限也很明显：

- 需要高质量推理示范；
- 模型主要在模仿已有路径；
- 错误或冗长的 Teacher 轨迹也会被学习；
- 数据只给一种解法时，可能压制其他有效策略。

所以 SFT 更像老师把完整解题过程写在黑板上，学生逐步模仿。

---

## 4. CoT 的第二条来源：通过 RL 从结果奖励中探索

RL 可以只给问题和可验证的最终答案，不规定中间推理必须写成什么样。

例如，同一道数学题生成多条回答：

```text
回答 A：直接猜 4                  → 正确，reward=1
回答 B：分步推理后得到 4          → 正确，reward=1
回答 C：分步推理但最后得到 5      → 错误，reward=0
回答 D：重新检查并修正为 4        → 正确，reward=1
```

RL 提高获得高 reward 的整条生成轨迹的概率。若在模型当前能力范围内：

```text
带有效推理/验证的回答
比直接猜测更容易答对
```

那么经过大量采样和更新后，这些行为会被间接强化：

```text
更长但有效的推理
→ 更高正确率
→ 更高 reward
→ 该类轨迹概率提高
→ 后续更容易再次生成
```

这里非常关键：**reward 不直接告诉模型“你必须写 CoT”**。模型只是发现某些带分解、重算、验证的轨迹更容易获得正确结果，于是这些轨迹在训练中被保留下来。

这就是“incentivize（激励）”与“imitate（模仿）”的区别：

- SFT：给模型正确推理轨迹，让它模仿；
- RL：给结果目标，让模型探索能获得高 reward 的轨迹。

## 5. 最终答案 reward 怎样影响中间 CoT token？

这是我们前面讨论的 credit assignment 问题。

一条回答由 token 序列组成：

\[
o=(a_1,a_2,\ldots,a_T)
\]

整个回答的概率为：

\[
\pi_\theta(o\mid q)
=\prod_{t=1}^{T}
\pi_\theta(a_t\mid q,a_{<t})
\]

取 log 后乘法变为加法：

\[
\log\pi_\theta(o\mid q)
=\sum_{t=1}^{T}\log\pi_\theta(a_t\mid q,a_{<t})
\]

最朴素的序列级 Policy Gradient 会把同一个 advantage 乘到整条回答的每个生成 token：

\[
L
=-A(o)\sum_{t=1}^{T}
\log\pi_\theta(a_t\mid q,a_{<t})
\]

因此：

- 正确回答中的推理 token 和答案 token 都被整体鼓励；
- 错误回答中的 token 都被整体抑制；
- 算法并不知道究竟哪个中间 token 是“功臣”或“罪魁祸首”。

这是一种粗粒度信用分配。PPO 可以借助 Critic/GAE 得到随时间变化的 advantage；过程奖励模型（PRM）则尝试直接评价中间推理步骤。但过程监督是否可靠、是否会被模型投机，同样是难题。

nanochat 在 GSM8K 上使用的就是最简单的序列 advantage 广播方案，详见 [`../rl_GSM8K/rl.md`](../rl_GSM8K/rl.md)。

## 6. DeepSeek-R1-Zero 与 “Aha Moment”

DeepSeek 团队在 2025 年发布的论文 [DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning](https://arxiv.org/abs/2501.12948) 中报告：R1-Zero 直接在 base model 上进行大规模强化学习，没有先使用 reasoning SFT cold start。

论文描述的一个现象是：训练中间阶段，模型学会为困难问题分配更多思考时间，并会重新评估先前方法。这被称为 **Aha Moment**。

可观察行为包括：

- 回答长度随训练增加；
- 主动检查先前推导；
- 发现错误后重新选择路径；
- 使用类似 “wait” 的转折语言；
- 尝试替代解法和自我验证。

理解这个现象时，应避免两个极端。

### 极端一：把它解释成“模型突然有了意识”

没有必要。模型仍然是通过 next-token prediction 生成序列，RL 改变的是各种生成轨迹的概率。反思样式之所以增加，是因为它们与较高的最终 reward 相关。

### 极端二：认为它只是人类提前写好的模板

R1-Zero 的重要观察恰恰是：在没有显式 reasoning SFT 示范的条件下，规则型可验证 reward 也能够激励某些反思、自我纠错和延长计算行为。

更准确的说法是：

> 模型在预训练阶段已经潜在地具备多种语言和推理行为；RL 提供选择压力，使其中更容易带来正确答案的行为概率上升，并组合成更稳定的推理策略。

## 7. “OpenAI 恭喜 DeepSeek 独立发现”应该怎样理解？

我们讨论过一个行业轶事：DeepSeek-R1 发布后，有观点带着“这些规律 OpenAI 在 o1 中可能已经发现，只是没有公开”的语气评价 DeepSeek 的结果。

这类说法不宜在没有一手出处时当作确定引语。更可靠的理解是：

- OpenAI o1 先展示了 inference-time reasoning 与 RL 后训练能显著提升推理能力；
- OpenAI 没有公开完整训练细节；
- DeepSeek-R1 公开了 GRPO、规则型 reward、R1-Zero 和 Aha Moment 等关键实验；
- DeepSeek 的重要贡献不仅是得到相似结论，还包括开放模型、论文和可复现的技术路线。

所以真正重要的问题不是“谁先知道”，而是：**什么训练条件能稳定复现这种能力跃迁？**

## 8. 为什么并不是所有模型做 RL 都能出现能力涌现？

RL 不是从零创造任意能力。它通常需要 base model 已经偶尔能够生成正确或有价值的轨迹。

假设某题采样 16 次：

```text
全部错误 → 组内 reward 相同 → GRPO advantage 接近 0
全部正确 → 组内 reward 相同 → 同样没有区分度
有对有错 → 才能相对强化正确轨迹
```

所以能力提升依赖整条链：

```text
强基础模型
→ 合适难度的任务
→ 足够多样的 rollout
→ 可靠且不可作弊的 verifier
→ 有区分度的 reward
→ 稳定的 RL 优化
→ 严格评估
```

## 8.1 基础模型：能否探索到正确轨迹

如果模型生成成千上万次也从不答对，RL 没有正向轨迹可强化。预训练与 SFT 决定了探索空间的起点。

## 8.2 任务课程：是否位于能力边界

最有训练价值的任务通常不是最简单或最难，而是当前模型“有时能做对、有时会做错”的题。

对于二元 reward，若答对概率为 \(p\)，reward 方差为：

\[
p(1-p)
\]

它在 \(p=0.5\) 附近最大，在 \(p=0\) 或 \(p=1\) 时为 0。

## 8.3 Rollout 算力：能否发现稀有好策略

同一道题采样 4 次可能全部失败，采样 64 次才可能发现一条正确而新颖的轨迹。RL 的重要成本不仅是 backward，还包括大规模生成。

## 8.4 Verifier：是否真的判断了“好”

数学最终答案和代码单元测试相对容易验证，但仍存在：

- 测试覆盖不足；
- 硬编码或 reward hacking；
- 超时和内存问题；
- 正确但不可读、不可维护；
- 最终答案正确但推理过程错误。

Reward 错了，模型只会更高效地学会钻漏洞。

## 8.5 优化稳定性：能否保留探索能力

RL 还可能发生：

- entropy collapse；
- 输出越来越长；
- 策略更新过大；
- 长短样本权重偏差；
- reward 噪声；
- 通用能力退化。

因此“都用了 GRPO”并不意味着训练系统相同。算法公式只是其中一个环节。

## 9. 编程能力为什么特别适合 RL，又为什么仍很难？

编程任务适合 RL，因为很多结果可以自动验证：

```text
能否编译
单元测试通过率
是否超时
是否超内存
静态检查是否通过
```

但核心壁垒往往不在 PPO/GRPO 公式，而在：

1. 高质量、真实且有区分度的题目；
2. 可重放的代码仓库与环境；
3. 覆盖充分的隐藏测试；
4. 安全执行沙箱；
5. 防止读取测试、硬编码和其他 reward hacking；
6. 能把失败类型、过程质量和最终结果结合的 verifier；
7. 足够强、能偶尔探索到正确 patch 的 base model；
8. 大规模 rollout 与稳定训练基础设施。

因此 DeepSeek 或其他强推理模型的能力，不应简单归因于“使用了 GRPO”。更准确的理解是：

> GRPO 是把 reward 转成梯度的算法；真正决定训练上限的是基础模型、任务分布、rollout、verifier、reward 和工程稳定性的共同质量。

## 10. CoT 是结果、工具，还是目标？

三种情况都可能成立，但要区分。

### CoT 作为训练目标

SFT 中标准推理文本就是 target，模型被直接要求模仿。

### CoT 作为解决问题的工具

RL 不要求特定文字，只奖励最终正确。模型发现中间推理能提高成功率，于是更多使用它。

### CoT 作为可观察结果

研究者看到推理长度增加、反思和修正出现，把它们称为能力涌现。但可见 CoT 不一定忠实反映模型内部全部计算，也不应自动等同于可靠推理。

最终应评价的是：

- 正确率是否提高；
- 分布外任务是否泛化；
- 推理是否稳定；
- 是否真的使用证据；
- 是否存在 reward hacking；
- 增加的 token 是否带来有效收益。

## 11. 最终心智模型

```text
预训练
  学到语言、知识和潜在推理模式
      ↓
SFT CoT
  模仿人类/Teacher 提供的推理轨迹
      ↓
RL 探索
  对同一问题生成多条候选轨迹
      ↓
Verifier / Reward
  判断哪些轨迹更可能带来正确结果
      ↓
Policy Gradient
  提高高 reward 轨迹中 token 的概率
      ↓
行为分布变化
  分解、验证、自我纠错等行为可能更频繁
      ↓
评估与再训练
  判断是真正泛化，还是只学会拉长回答或钻奖励漏洞
```

一句话总结：

> **CoT 并不是 RL 凭空创造的一段神秘思维。预训练提供潜在能力，SFT 可以直接示范推理，RL 则通过结果奖励选择和强化更有效的生成轨迹。所谓能力涌现，是这些潜在行为在规模、探索和选择压力下突然变得稳定、明显和可复用。**
